# 砚台输入法 · Inkstone

在 Obsidian 里绕开 iPadOS 系统中文输入法，直接输入中文。

在特定 iPadOS 环境下，系统拼音配合外接键盘会出现可见的输入延迟。砚台绕开这条路径：把系统键盘留在英文输入源接收按键，在编辑器内用本地 RIME 完成转换和上屏。

> 延迟的具体成因尚未定论。早期用 `log show --signpost` 采到的键盘埋点曾指向自动改正环节，但后续对照测试没有复现出稳定的因果关系，因此这里只陈述可观察到的现象。

拼音引擎用 [RIME](https://rime.im/)，通过 [My RIME](https://github.com/LibreService/my_rime) 的 WebAssembly 构建。

## 适用范围

**iPad + 外接键盘**。这是它要解决的场景，也是实机验证过的场景。

> 桌面版 Obsidian 也能加载（开发期间一直在 macOS 上验证），但它要解决的那个延迟问题只在 iPad 上存在。

## 怎么用

**1. 把系统键盘切到英文 ABC** — 砚台随即接手，可以打中文了。

**2. 按 Shift 切中英文** — 单独按一下，中间不夹别的键。切换键可以在插件设置里改成 Control / Option / Command，或者关掉只用命令。

**3. 系统键盘切回拼音，砚台自动让位** — 按键归系统输入法，砚台停止工作。

两种状态砚台都会主动告诉你，不用猜：

- 接手时：「砚台输入法已就绪——按 Shift 在中英文之间切换」
- 让位时：「系统键盘切到中文了，砚台已停止工作——按键现在归系统输入法」

除了切换键，也可以点状态栏、点左侧 ribbon 图标，或用命令「切换中英文 (toggle)」——插件不预设快捷键，需要的话在 Obsidian 的快捷键设置里自行绑定。

### 为什么会有「让位」这回事

系统键盘的中英切换（`Ctrl+空格` / 🌐 地球键）和砚台的中英切换（Shift）是**两个独立的开关**。系统键盘一旦切到拼音，按键在到达插件之前就被系统输入法吃掉了，砚台在任何模式下都不工作。

砚台查不到系统输入源（网页环境没有这个 API），只能从事件反推：有 composition 提交了汉字，说明系统接管了；之后再有正常字符键落进编辑器，说明系统交还了控制权。提醒只在**当下真的发生**时响，不做任何预判。

### iPad 屏幕键盘

软键盘的 Shift 一般不把事件发给网页。用 Obsidian 自己的出口——**设置 → 移动端 → 管理工具栏选项**，把「砚台输入法：切换中英文」加进去，键盘正上方就有一键切换。

软键盘本身尚未实机验证，见「验证状态」。

## 表情

用系统的 🌐 **地球键**调出表情面板，点了直接进文档。

iPadOS 有时不会把表情面板的点击变成文本（同样的动作时好时坏）。砚台会接管这类按键并自己写进文档，所以是稳定的。

> 地球键能否调出表情，取决于你的键盘列表里启用了「表情符号」（设置 → 通用 → 键盘 → 键盘）。另外留意它循环到哪个键盘：如果落到简体拼音，砚台就会让位。

## 安装

把 Release 里的 `main.js`、`manifest.json`、`styles.css` 放进 Vault 的 `.obsidian/plugins/inkstone/`，重启 Obsidian 后在「设置 → 第三方插件」启用「砚台输入法」。

**运行时不联网。** RIME 引擎、引擎数据和拼音方案全部随 `main.js` 一起分发，首次启动也不需要网络。`main.js` 因此约 6.6 MB。

构建期的抓取过程见 `scripts/fetch-assets.mjs`，来源与 sha256 记录在 `src/assets/ASSETS.json`。

## 命令

命令名都带英文别名，系统键盘是英文时也搜得到。

| 命令 | 作用 |
|---|---|
| 切换中英文 (toggle) | 与 Shift 等价 |
| 切换表情模式 (emoji) | 插件内置的离线表情输入 |
| 诊断报告 (report) | 环境、初始化耗时、按键捕获统计、最近事件轨迹 |
| 诊断：把报告存进 Vault (save report) | 写成笔记，随 Obsidian Sync 到别的设备排查 |
| 诊断：开始/停止记录按键事件 (trace) | 事件轨迹**默认关闭**，需要排查时才开 |
| 诊断：记录原始按键内容 敏感 (trace raw) | 单独开启才会记录你实际敲了什么 |

默认记录是**脱敏**的：`key=<字母>` / `code=<字母键>` / `kc=<内容>`。具名键（`Shift`、`Escape`、`Unidentified`）和关键信号（`keyCode=229`、`code=""`）原样保留，足以判断键盘行为，但还原不出输入内容。脱敏发生在写入时刻，事后开启敏感模式不会回溯暴露已记录的按键。

## 验证状态

实测环境：iPad Pro 11 英寸（M1）、iPadOS 27.0、Obsidian 1.13.7、妙控键盘。

已验证：

- iPad 外接键盘下中文输入流畅，核心假设成立
- 桌面：完全内嵌的引擎离线初始化成功（就绪 305ms），`yanchi` 出候选、空格上屏一次不重复
- 系统键盘切换时的接手 / 让位提示
- 地球键调出的表情稳定进入文档
- 桌面（macOS）：候选栏跟随光标、空间不足时翻到上方、空格上屏一次不重复、Shift 切中英文、诊断报告

尚未验证：

- iPad **屏幕键盘**。插件只挂 `keydown`，iOS 软键盘未必给出可用的 `key` 值。

## 已知限制

- 输入拦截挂在 `document` 捕获层，绕开了 CodeMirror 的扩展优先级体系，可能与其他插件的快捷键冲突。
- 失焦、切换笔记、鼠标移动光标、切换窗格时的组合态重置尚不完整。
- 暂未处理所有 Markdown 快捷键、候选翻页按钮和用户设置界面。
