# 砚台输入法 · Inkstone

在 Obsidian 编辑器内部直接输入中文和表情，绕开 iPadOS 系统中文拼音输入的延迟。

iPadOS 的系统拼音在每次按键时都会跑一遍端上语言模型做自动改正，中位耗时 100ms 以上，打字会明显滞后。砚台不走系统输入法那条路：它在编辑器里接管按键，自己出候选、自己上屏。

拼音引擎用的是 [RIME](https://rime.im/)（通过 [My RIME](https://github.com/LibreService/my_rime) 的 WebAssembly 构建），表情词库是内置的。

## 当前功能

- iPad 和桌面版 Obsidian 均可加载（不是桌面专用插件）
- 全拼简体中文
- 候选词栏跟随光标；空格/数字选词、退格和方向键
- **Shift 切中英文**（外接键盘按一下，中间不夹别的键）。也可以用 `Cmd/Ctrl+Shift+Space`、点状态栏、点 ribbon 图标
- 表情模式：单独的命令「切换表情模式」，内置 269 个常用表情，打关键词搜索（`xiao` / `smile` / `huo` 都行），数字 1-7 或空格上屏。完全离线。在表情模式下按 Shift 直接回中文
- 命令面板中的“诊断报告”：环境、初始化耗时、按键捕获统计和最近事件轨迹

## 怎么切模式

**外接键盘**：单独按一下 Shift（中间不夹别的键），中 ↔ 英。表情不在这个循环里——Shift 只管中英文，和其他输入法的习惯一致。

**iPad 屏幕键盘**：软键盘的 Shift 一般不把事件发给网页，用 Obsidian 自己的出口——**设置 → 移动端 → 管理工具栏选项**，把「砚台输入法：切换中英文」加进去，键盘正上方就有一键切换。

**表情**：iPad 外接键盘上按系统的 🌐 地球键最顺手，它直接调出系统表情面板，砚台不拦。需要插件自带的表情输入时（离线、拼音搜索、桌面端），用命令「砚台输入法：切换表情模式」。

> 地球键出表情依赖你的键盘列表里启用了「表情符号」（设置 → 通用 → 键盘 → 键盘），不是所有设备都一样。另外要留意它循环到哪个键盘——如果落到简体拼音，回到砚台的英文模式打字就会出中文（0.7.2 起会提醒你）。

**两个开关，别混淆**：系统键盘的中英切换（`Ctrl+空格` / 🌐 地球键）和砚台的模式切换（Shift）是两回事。砚台在**英文模式下完全不拦截按键**，打出中文还是英文取决于系统输入源。所以英文模式要配合系统键盘的英文 ABC 才对。

砚台查不到系统输入源（网页环境没有这个 API），只能从事件反推。提醒只有一条，且只在**当下真的发生**时响：英文模式下有 composition 提交了汉字，说明系统中文输入法正在转换。不做任何预判——凭记忆猜的提醒必然误报。

**表情模式**用法：进入后直接打关键词，`xiao` 出 😀😄😁，`huo` 出 🔥🚀，`zan` 出 👍。数字 1-7 选，空格选第一个，退格改查询，Esc 清空。查询为空时只吃字母，空格退格照常工作。

苹果自带的表情面板插件调不动（网页环境没有这个 API），但也没被挡住：`Ctrl+Cmd+Space`（macOS）和 iPad 的 🌐 键照常可用。

## 安装

将发布包中的 `main.js`、`manifest.json`、`styles.css` 放入 Vault 的：

`.obsidian/plugins/inkstone/`

然后重启 Obsidian，在“设置 → 第三方插件”中启用“砚台输入法”。iPad 系统键盘必须切换到英文 ABC。

首次启动需要联网下载 RIME 引擎资源和简体拼音词库（来自 jsDelivr CDN），之后词库数据会缓存在 Obsidian 的 WebView 数据中。离线首次安装目前不可用。

## 验证状态（0.4.0）

已实机验证：

- **iPad**：M1 iPad Pro / iPadOS 27 / 外接键盘 / 系统输入源为英文 ABC，中文输入流畅。核心产品假设成立——在编辑器内拦截硬件键盘事件、用独立 RIME 引擎出候选，可以绕开系统拼音路径的卡顿。
- **桌面（macOS）**：候选栏跟随光标、空间不足时翻到上方、空格上屏一次不重复、Shift 中英切换、诊断报告。

尚未验证：

- iPad **屏幕键盘**。插件只挂 `keydown`，而 iOS 软键盘未必给出可用的 `key` 值。软键盘下的中英切换目前只能靠 Obsidian 移动端工具栏按钮。
- 冷启动无网络 / CDN 不可达时的表现。

## 诊断

命令面板里有四个诊断命令：

- **诊断报告** — 环境、初始化耗时、按键捕获统计、最近事件轨迹
- **诊断：开始/停止记录按键事件** — 事件轨迹**默认关闭**，需要排查时才开
- **诊断：记录原始按键内容（敏感）** — 单独开启才会记录你实际敲了什么
- **诊断：网络探测** — 按需检查 CDN 可达性，不再拖慢启动

默认记录是**脱敏**的：`key=<字母>` / `code=<字母键>` / `kc=<内容>`，具名键（`Shift`、`Escape`、`Unidentified`）和关键信号（`keyCode=229`、`code=""`）原样保留，足以判断软键盘行为，但还原不出输入内容。脱敏发生在写入时刻，事后开启敏感模式不会回溯暴露已记录的按键。

## 已知限制

- 输入拦截挂在 `document` 捕获层，绕开了 CodeMirror 的扩展优先级体系，可能与其他插件的快捷键冲突。
- 失焦、切换笔记、鼠标移动光标、切换窗格时的组合态重置尚不完整。
- 暂未处理所有 Markdown 快捷键、候选翻页按钮和用户设置界面。
- 拼音引擎依赖 My RIME 0.10.9 的 WebAssembly Worker。源项目采用 AGPL-3.0-or-later 许可，砚台也以同一许可发布。
